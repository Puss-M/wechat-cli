# 个人记忆 Web App 设计基线

## 产品定位

这是一个服务于单个用户的本地优先个人记忆 Web App。它读取微信朋友圈导出的 JSON、SQLite 归档和本地图片，生成年度刊物、月度小记、最近回忆、时间地图和今日回忆。

产品目标是把零散朋友圈变成可阅读、可回看、可持续补充的私人生活刊物。它不把缓存范围外的历史伪装成完整人生记录。

## 信息架构

- 年度总览：首页首屏展示年份、代表图片、朋友圈数量、活跃月份、主要地点和数据覆盖状态。
- 年度刊物：以年份为主线，按月份阅读章节。
- 最近回忆：按时间倒序浏览单条朋友圈。
- 时间地图：按地点名称和城市聚合，再进入对应时间线；无坐标时不伪造地图位置。
- 今日回忆：匹配月日，明确区分无记录和未覆盖。
- 回忆旅程：把时间线、地点索引和代表性图片组合成跨年份的个人旅程页面。
- 数据状态：常驻显示已提取范围、记录数量、图片数量和未覆盖月份。

年度首页使用记录覆盖月份最多、且有代表性图片或文字的年份作为默认入口；如果没有可比较的完整年份，则回退到最近有记录的年份。年度目录显示 12 个月，并区分“已覆盖”“已覆盖但无记录”和“未覆盖”。

## 视觉方向

采用私人杂志感：温暖米白或浅灰底色、墨色正文、衬线标题、窄正文栏、大留白、章节标题、图片拼贴和横向时间线。年度封面像生活刊物，不使用营销式 Hero。

桌面端使用目录与内容双栏；手机端使用单列阅读。图片优先于统计信息；缺图时显示真实缺失状态。卡片只用于单条回忆和月份条目，不把整页堆成卡片网格。

## 数据与可信度

- 原始 JSON、SQLite 和 assets 只读保存。
- 用户标题、注释、精选标记写入独立的 `annotations.json`。
- 未覆盖、图片缺失、来源不完整和无法归属时间必须传递到页面。
- 报告摘要只使用确定性统计，不把推测性情绪或人生结论写成事实。
- 没有图片证据时不生成破损图片框；没有坐标时不生成精确路线。

## 首版实现

采用静态记忆刊物与轻量本地数据库应用的组合：页面读取现有归档 SQLite，使用独立注释文件保存编辑内容。首版支持年度总览、年度刊物、月度小记、年度报告、最近回忆、时间地图、今日回忆和回忆旅程，以及覆盖状态和图片索引。

图片管线默认解码本机缓存中能够通过本人朋友圈帖子 ID 与图片 ID 确认归属的图片；无法解码或无法确认归属的图片显示缺失状态，不从其他账号缓存中猜测或混入。

性能按数万条朋友圈和图片设计：首页使用摘要数据，图片懒加载和缩略图；报告生成失败不覆盖已有结果。默认只绑定本机，不上传朋友圈数据或微信数据库。

## 明确不做

- 多用户账号、社交分享和默认云同步
- 没有证据支持的 AI 情绪分析
- 依赖地图服务的精确路线还原
- 自动替用户删除或公开隐私内容

## 决策记录

1. 选择年度生活刊物作为主结构，因为它最贴合月度小记、年度报告和回忆旅程。
2. 保留时间地图和今日回忆作为辅助入口，增加日常回看能力。
3. 采用本地优先，避免私人数据上传和云端依赖。
4. 用覆盖状态区分“无记录”和“未覆盖”，避免缓存不完整造成误导。
5. 原始数据只读，用户编辑放在独立注释层，保证可重建和可回滚。
6. 首版先做确定性统计与阅读体验，AI 叙事延后到数据质量稳定之后。
