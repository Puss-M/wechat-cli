# 朋友圈个人记忆库设计

## 1. 目标

在本机离线保存用户自己发布的朋友圈，并从同一份可追溯归档生成：

- 月度小记
- 年度报告
- 回忆旅程

第一阶段只处理用户自己发布的朋友圈，不纳入聊天记录、他人朋友圈、收藏或自动发布。

## 2. 数据链路

```text
微信本地缓存 / 用户确认的 UI 采集
        |
        v
规范化归档库 + 原始快照 + 媒体资产包
        |
        +--> 月度小记
        +--> 年度报告
        +--> 回忆旅程
```

报告只能从规范化归档库生成，不能直接读取一次性导出的 Markdown。

## 3. 归档记录

每条记录至少包含以下字段：

| 字段 | 说明 |
| --- | --- |
| `moment_id` | 微信帖子 ID；UI 无 ID 时使用独立的 capture ID |
| `created_at_epoch` | 原始 Unix 时间戳；不可丢弃 |
| `created_at_local` | 按归档时区格式化的时间 |
| `timezone` | 时间所属时区 |
| `time_precision` | `second`、`minute`、`day` 或 `unknown` |
| `text` | 原始文字 |
| `media` | 图片、视频、音频、卡片等媒体项 |
| `location` | 原始地点和坐标；报告层再做归一化 |
| `source` | `local_sns_cache` 或 `wechat_ui` |
| `verification` | `xml_author`、`user_confirmed_ui` 或 `unknown` |
| `captured_at` | 本次采集时间 |
| `capture_batch_id` | 采集批次 |
| `content_hash` | 用于重复导入检测 |
| `status` | `complete`、`incomplete`、`invalid` 或 `superseded` |
| `annotations` | 用户备注、主题、心情、人物、事件和精选标记 |

原始 XML、UI 截图和诊断信息作为不可变快照保留。规范化记录可以被后续快照修正，但不能删除原始证据。

## 4. 合并与完整性规则

1. XML 帖子优先使用稳定的微信 `moment_id` 去重。
2. UI 记录不能仅使用“日期 + 文字”去重；无稳定 ID 时必须保留独立 capture ID，并记录可能重复关系。
3. 所有时间分组使用完整年份和原始 epoch；只有月日的 UI 记录标记为 `unknown`，不能强行归入年度报告。
4. 没有文字但存在图片、地点、链接或截图的记录必须保留。
5. 每次导入生成新的快照，并记录新增、更新、重复、失效和无法归属的数量。
6. 报告必须展示采集范围、缺失月份、未验证记录和媒体缺失数量。

## 5. 媒体资产包

媒体文件放在归档目录内，记录相对路径、内容 hash、大小、格式、来源和状态：

```text
archive/
  moments.sqlite
  snapshots/
  assets/
    <sha256>.<ext>
  manifests/
    <capture-batch-id>.json
  reports/
```

原始微信 URL 只作为来源元数据保存，报告默认不直接暴露带签名的 URL。无法取得的媒体保留 `missing` 状态，不生成空文件。

## 6. 报告契约

### 月度小记

- 发帖数和活跃天数
- 图片、链接、地点数量
- 主题和人工精选内容
- 时间线原帖索引
- 数据覆盖范围和缺失说明
- 可选叙事总结

### 年度报告

- 月度趋势
- 年度重要节点
- 高频地点和主题
- 媒体统计
- 代表性朋友圈索引
- 缺失月份、未验证记录和恢复限制

### 回忆旅程

- 按时间排序的事件节点
- 地点聚类和路线视图
- 图片与原文
- 用户备注、主题和心情
- 可隐藏或脱敏的分享版本

第一版先输出 Markdown 和自包含 HTML；PDF 属于后续渲染目标。

## 7. 实现阶段

### 阶段一：归档底座

- canonical schema
- 快照导入和 upsert
- 稳定时间与身份处理
- 媒体 manifest
- 覆盖率和缺失诊断

### 阶段二：月度小记

- 月份筛选
- 统计聚合
- 原帖索引
- Markdown/HTML 模板
- 可选叙事接口

### 阶段三：年度报告

- 从月度归档聚合
- 跨月统计
- 年度节点和缺失标记

### 阶段四：回忆旅程

- 地点归一化和聚类
- 人工标签与精选
- 时间线和地图数据
- 搬运与隐私分享预览

当前阶段一至四的确定性本地报告链路已实现：`archive-moments` 负责规范化归档，`report --kind monthly|yearly|journey` 负责生成 Markdown 或 HTML。主题、心情、人物、事件和精选字段已预留在 `annotations` 中；AI 叙事仍是后续可选能力，不作为数据完整性的替代品。

## 8. 验收标准

- 同一批数据重复导入不会重复计数。
- 跨年、同日同文和无年份日期不会错误合并。
- 空文字但有媒体或截图的帖子不会静默丢失。
- 报告能显示缺失月份和未验证记录。
- 归档目录移动到另一位置后，HTML 和媒体仍能正常打开。
- 月报和年报可由同一份归档重复生成，结果稳定。
- 现有 `moments` 导出行为和隐私边界保持兼容。
